## 0. 한 장 요약

| 항목 | 결정 |
|---|---|
| 모드 | ① **같이 깨기** (2인 협동, 스토리 스테이지) ② **용 대결** (1:1 실시간) ③ 둥지 지키기 (나중 — 상대의 방어 덱과 혼자 싸움) |

| 제작 시간 | Opus 5.5 높음 기준 10~15시간 (싱글 완성 뒤) |

## 1. 왜 이 방식인가

### 1.1 이 장르는 주고받을 것이 적다

- 한 판(약 90초)에 누르는 버튼 : 출격 약 70번 + 화로 7번 이하 + 브레스 2~3번 + 스킬 4번 이하 + 포효 0~1번 → **1초에 1번이 안 된다.**
- 필드의 용 · 좀비 65마리는 누른 버튼의 **결과**일 뿐이다. 버튼만 같으면 결과도 같다.

### 1.2 전투 코어가 처음부터 "같은 입력 → 같은 결과"다

- 코어는 `+ − × ÷` 와 `floor/round/min/max/abs`, 씨앗 난수만 쓴다 (기획서 5.11). 기기 · 브라우저가 달라도 같은 값이 나온다.
- `sim/engine.js` 가 이미 2명을 받는다 : 협동(`loads` 에 같은 편 둘) · 대결(`pvp: true`, 양쪽 한 명씩).
- 상태를 한 숫자로 줄이는 `hashState(S)` 가 있어 **어긋났는지 바로 안다.**

### 1.3 방식 비교

| 방식 | 보내는 것 | 판정 |
|---|---|---|
| 방장이 전부 계산해서 화면 상태를 보냄 | 유닛 65개의 위치 · 체력 × 1초 5번 | ✗ 데이터가 수십 배, 손님 화면이 끊긴다, 규칙에 넣을 필드가 많다 |
| 각자 따로 하고 점수만 비교 (신발 · 줄넘기 방식) | 진행도 | ✗ 같은 전장에서 같이 싸울 수 없다 → 협동 · 대결이 안 된다 |
| **버튼 누름만 주고받기 (명령 락스텝)** | 버튼 누름 + 시계 | ✔ 가장 가볍고, 코어를 그대로 쓰고, 속임수에 강하다 |

> 드래곤 결투(`DRAGON_DUEL_PLAN.md`)에서는 락스텝을 **버렸다** — 그 게임은 난수 쓰는 곳이 122군데이고 계산 간격이 일정하지 않아서다. 이안 드래곤은 **처음부터** 고정 간격 · 씨앗 난수로 설계했기 때문에 쓸 수 있다.

## 2. 모드

### 2.1 같이 깨기 (2인 협동)

**무엇** : 친구와 같은 편이 되어 스토리 스테이지를 깬다.

| 규칙 | 내용 |
|---|---|
| 기지 | **하나를 같이 쓴다.** 체력 = 둘 중 높은 쪽 × 1.5 |
| 불씨 · 화로 | **각자.** 내 화로는 내가 올린다 |
| 덱 · 리더 · 브레스 · 스킬 · 포효 | 각자 자기 것 (레벨도 자기 것 그대로) |
| 필드 용 상한 | 한 사람당 13마리 (25 ÷ 2 + 1). 제한 출격 스테이지도 같은 식 |
| 좀비 처치 불씨 | 둘이 반씩 |
| 좀비 세기 | 싱글의 **1.5배** (체력 · 공격). 화로가 둘이라 불씨가 많기 때문 — 초기값이고, 제작 때 계산기로 2인 자동 전투를 돌려 확정한다 |
| 배속 · 일시정지 | 없음 (1배속 고정) |
| 고를 수 있는 스테이지 | 방장이 열어 둔 스테이지 (깬 것 + 바로 다음 것) |

**보상**

- 코인 : 싱글과 같은 규칙 (첫 클리어 / 다시 깨기 40%) + 우정 보너스 10%.
- **끌어 주기** : 손님이 아직 못 깬 "다음 차례" 스테이지를 같이 깨면 손님도 **별 1개로 첫 클리어 인정.** 막힌 친구를 형 · 누나가 끌어 줄 수 있다. 별 2 · 3개는 혼자 깰 때만 받는다.
- 손님 차례보다 뒤 스테이지면 손님은 다시 깨기 코인만 받는다 (진행은 안 건너뛴다).

**재미 포인트**

- 역할 나누기 : "나는 방패, 너는 대포". 화로를 한 명이 먼저 올리고 한 명이 버틴다.
- 브레스 2개 · 스킬 4번 · 포효 2개 → 타이밍을 맞추면 보스가 녹는다.
- 빠른 말 버튼 4개 (오락실 방 채팅을 그대로 씀, 글자 입력 없음) : 「방패 부탁!」 「브레스 간다!」 「화로 올릴게!」 「최고!」

### 2.2 용 대결 (1:1)

**무엇** : 양쪽이 모두 사람. 좀비는 없다. 상대 둥지를 먼저 무너뜨리면 이긴다.

| 규칙 | 내용 |
|---|---|
| 전장 | 길이 1,000wu · 좀비 줄 없음 (`pvp: true, lines: []`) |
| 시간 | 제한 180초. **불꽃 타임 90초부터** (공격 ×1.5, 30초 뒤 ×2) |
| 시간이 끝나면 | 기지 체력 %가 높은 쪽 승. 같으면 무승부 |
| **공정하게** | 모든 용 **Lv20 · 3단 모습 고정.** 용사단 레벨 20 고정. 연구소 · 보물 · 「+」 **미적용** |
| 덱 | **6칸 고정**, 가진 용만. 전설은 1마리까지 |
| 스킬 · 브레스 · 포효 | 그대로 (스킬 2개, 각 2번) |
| 현상금 | 상대 용을 쓰러뜨리면 그 용 값의 20% 불씨 |
| 화면 | 누구나 **자기가 왼쪽** (오른쪽 편은 화면만 좌우로 뒤집어 그린다) |
| 정보 | 상대 덱은 시작 전 3초 공개. 판 중에는 상대 **화로 레벨만** 보인다 (불씨는 안 보임 → 눈치 싸움) |
| 열리는 때 | 2-10 클리어 (덱 6칸이 열릴 때) |
| 상대 | **친구 초대만** (비공개 방). 모르는 사람 자동 매칭 · 랭킹은 안 한다 |
| 보상 | 승 200 코인 · 패 80 코인, 하루 5판까지. 젬 없음. 전적(승/패)만 기록 |

**재미 포인트** : 싱글의 "화로 딜레마"가 눈치 싸움이 된다 — 화로를 올리는 순간이 빈틈이다. 싼 용으로 몰아칠까, 버티며 큰 용을 준비할까.

### 2.3 둥지 지키기 (나중)

- 내 덱을 "방어 덱"으로 Firestore 에 올려 둔다. 다른 사람이 **혼자** 그 덱(기준 AI 가 조종)과 싸운다.
- 실시간 연결이 필요 없어 가장 싸다. 싱글 + 실시간 멀티가 자리 잡은 뒤에 검토한다.

### 2.4 안 하는 것

3~4인전 · 관전 · 모르는 사람과의 랭크전 · 판 도중 다시 들어오기.

## 3. 주고받는 방법 (명령 락스텝)

### 3.1 시작

1. 대기실에서 각자 **편성**을 방에 올린다 (`players/$uid/ld`, 3.5).
2. 방장이 시작 → 기존 `startCountdown` 이 서버 시각 `startAt` 을 정한다.
3. 두 기기가 같은 재료로 전투를 만든다 : `createBattle(stage, loads, D, seed)` — `seed` 는 방의 `seed`, `loads` 는 두 사람의 편성.
4. 자리 번호 : `joinedAt` 이 빠른 사람이 0번, 다음이 1번 (같으면 uid 순). 대결은 0번이 왼쪽 편.
5. 시계 : **틱 n 의 시각 = `startAt` + n ÷ 30 초.** 각 기기는 `serverNow()` 로 "지금 몇 틱인지"를 안다.

### 3.2 버튼을 누르면

```
누름 (지금 틱 P)  →  명령 { 실행 틱 = P + 12, 종류, 번호 }   ← 0.4초 뒤에 실행하기로 약속
                 →  0.2초마다 한 번씩 묶어서 방에 쓴다 (1초 5번)
양쪽 기기 모두 "실행 틱"이 되었을 때 그 명령을 코어에 넣는다
```

- **입력 지연 12틱(0.4초)** 은 연출로 가린다 : 누르는 순간 버튼이 눌리고 소리가 나고, 둥지 문에서 용이 "뿅" 하고 나오는 0.4초짜리 그림이 돈다. 브레스는 리더가 숨을 들이쉬는 동작이 그 시간이다.
- 같은 틱에 여러 명령이 있으면 **자리 번호 → 보낸 순서** 로 넣는다 (두 기기가 같은 순서).

### 3.3 약속 시계 — 어긋나지 않게 하는 장치

- 0.2초마다 쓰는 묶음에는 **"틱 T 이전에 실행될 내 명령은 더 없다"** 는 약속(T = 지금 틱 + 12)이 들어 있다.
- 받는 쪽은 **상대가 약속한 틱까지만** 계산한다. 그래서 늦게 온 명령 때문에 어긋나는 일이 구조적으로 없다.
- 네트워크가 0.2초보다 더 늦으면 계산이 잠깐 멈췄다가(화면은 그대로) 도착하는 대로 빨리 감아 따라잡는다 (한 프레임에 코어 최대 6번 — 기획서 15.3 과 같은 장치).

| 기다린 시간 | 화면 |
|---|---|
| 0.5초 미만 | 아무 표시 없음 |
| 0.5초~ | 신호 아이콘이 깜빡 |
| 1.5초~ | 「연결 확인 중…」 띠 |
| 10초~ | 상대가 나간 것으로 처리 (3.6) |

### 3.4 방에 쓰는 값 (한 사람당 문자열 2개)

| 필드 | 언제 | 내용 | 크기 |
|---|---|---|---|
| `players/$uid/ld` | 대기실에서 1번 | 편성 (3.5) | 500자 이하 |
| `players/$uid/lk` | 판 중 0.2초마다 | 약속 틱 · 최근 해시 · 최근 명령 20개 | 300자 이하 |

`lk` 의 모양 (예) :

```
840|810:a3f9c2|57:846:s3,58:849:w,59:852:b
약속 틱 | 해시 잰 틱:해시 | 순번:실행 틱:명령, …
명령 : s0~s9 출격(덱 칸) · w 화로 · b 브레스 · k0 k1 스킬 · r 포효
```

- **최근 20개를 매번 다시 보낸다.** RTDB 는 중간 값을 건너뛰고 마지막 값만 줄 수 있어서, 한두 번 놓쳐도 명령이 사라지지 않게 하려는 것이다 (순번으로 중복을 거른다).
- 필드 하나를 덮어쓰기만 하므로 데이터가 쌓이지 않는다.

### 3.5 편성 (`ld`)

```js
{ v: '코어 버전-데이터 해시', d: [['kkomul', 12, 3], …], l: 'aquantis', q: 14,
  k: ['meteor', 'gust'], b: [연구소 7칸], t: [월드별 보물 단계 10칸] }
```

- 받은 쪽은 값을 **범위 안으로 자르고** 확인한다 (레벨 1~30 · 「+」 0~10 · 연구소 0~9 · 보물 0~3 · 없는 용 · 겹친 용 · 칸 수). 이상하면 시작하지 않는다.
- 대결에서는 **레벨 · 연구소 · 보물을 아예 읽지 않는다** (용 이름만 쓴다) → 레벨을 고쳐 보내도 소용없다.
- `v` 가 서로 다르면 「새로고침 해 주세요」. 오락실은 PWA 라서 한쪽이 옛 버전인 일이 실제로 생긴다 — 버전이 다르면 계산이 어긋나므로 **반드시** 막는다.

### 3.6 어긋남 · 끊김

| 상황 | 처리 |
|---|---|
| 같은 틱의 해시가 서로 다름 (5초마다 비교) | 그 판은 **무효** (보상 없음) + 「연결이 어긋났어요. 한 판 더?」. 기록을 남겨 원인을 찾는다. 정상이면 일어나지 않는다 |
| 상대가 10초 넘게 조용함 | 협동 : 남은 사람이 **혼자 이어서** 한다 (떠난 친구의 용은 그대로 싸우고 새로 안 나온다). 대결 : 남은 사람 승 |
| 내가 끊겼다 돌아옴 | 그 판에는 못 돌아온다. 결과 화면으로 간다 |
| 앱이 뒤로 감 (전화 · 홈 버튼) | 끊김과 같다 |

### 3.7 속임수

서버가 심판을 보지 않는 구조다 (오락실 전체가 그렇다). 다만 이 방식은 **상대 기기가 심판**이다.

- 불씨가 없는데 용을 내보내는 명령을 보내면 → 상대 기기의 코어가 그 명령을 **거절**한다 → 해시가 어긋나 판이 무효가 된다. 이득을 볼 수 없다.
- 남는 구멍 : 안 가진 용을 덱에 넣기 · 지고 있을 때 일부러 끊기. → **친구끼리만** 하게 해서 받아들인다 (모르는 사람 랭킹을 안 하는 이유).

## 4. 방의 흐름 — 있는 것을 그대로 쓴다

| 단계 | 쓰는 것 |
|---|---|
| 로비 | 새 화면 `IanDragonLobby.js` (「같이 깨기」 · 「용 대결」). 줄넘기 로비(`JumpRopeLobby.js`)와 같은 틀 |
| 방 만들기 | `createRoom({ isPrivate, game: 'idragon', maxPlayers: 2, … })` + 스테이지 번호(`idgStage`, 0 = 대결) |
| 초대 | 친구에게 기존 초대(받은 편지함 `challenge` 의 `{ code, game }`) |
| 들어가기 | 초대 수락 · 방 코드. 협동만 공개 방 목록 · 빠른 참가 허용 (목록은 개수 제한 조회) |
| 대기실 | 기존 대기실. 준비 → 방장 시작 → `startCountdown` |
| 시작 다리 | 새 파일 `startIanDragon.js` — `startJumpSurvival.js` 와 같은 모양 : 게임 묶음 불러오기 → `Room.holdRoomSeat(code)` → `nav.replace(IanDragonGame, { mode, code, room })` |
| 판 중 | `subscribeRoom` 으로 상대 `lk` 읽기 · 내 `lk` 쓰기 · 기존 `heartbeat` (5초) |
| 끝 | `finalizeResult` → 결과 화면 |
| 한 판 더 | 기존 방식 : 자리 유지 + `resetRoom(code, { round })` + 대기실로 |
| 나가기 | 화면을 떠날 때 구독 해제 (`onLeave`) · `leaveRoom` |

- 방의 옛 필수 값 7개(`nickname · characterId · ready · stairs · shoesFound · alive · joinedAt`)는 다른 게임들처럼 채워 넣는다 (`stairs · shoesFound` 는 0).
- 방과 통신하는 코드는 **`net/roomBridge.js` 한 파일**에 가둔다. 나중에 오락실이 서버를 옮겨도(Cloudflare 검토 중) 이 파일만 바꾸면 된다.

## 5. 화면

**같이 깨기**

- 내 덱 · 화로 · 브레스는 싱글과 똑같다.
- 위쪽에 친구 띠 : 얼굴 · 화로 레벨 · 브레스 준비 표시.
- 친구의 용은 머리 위에 작은 초록 깃발 (내 용은 깃발 없음).
- 빠른 말 4개는 왼쪽 가장자리에서 끌어내는 서랍.

**용 대결**

- 시작 전 3초 : 양쪽 덱 6칸과 리더를 마주 보여 준다.
- 판 중 : 위쪽에 상대 기지 체력 + 화로 레벨. 내 화면은 항상 내가 왼쪽.
- 끝 : 이긴 쪽 리더의 승리 동작 + 「한 판 더」.

**공통** : 신호 아이콘 3칸 · 배속 버튼 숨김 · 일시정지 대신 「나가기」(확인 창).

## 6. 비용 계산 (오락실 「새 게임 공식」 점검)

| 공식 | 이안 드래곤 |
|---|---|
| 내가 받는 양이 전체 사람 수에 비례하면 안 된다 | ✔ 방 안의 **1명** 것만 받는다 |
| 전체 목록 구독 금지 · 목록은 개수 제한 | ✔ 방 목록은 기존 제한 조회만, 구독 없음 |
| 화면에 있을 때만 구독, 떠날 때 해제 | ✔ |
| 보내는 빈도 상한 (위치류 1초 5번 이하) | ✔ 정확히 1초 5번, 판 중에만. 대기실에서는 0 |
| heartbeat 5초 이상 · presence 15초 이상 | ✔ 기존 값 그대로 |
| 새 서버 필드는 규칙과 같은 커밋 | ✔ 7장 |

**한 판** (150초 기준) : 5번 × 150초 × 2명 = 1,500번 쓰기 × 약 350바이트 ≈ **0.5MB 내려받기.**

- RTDB 무료 한도 월 10GB → 이안 드래곤만 쓴다면 **월 약 19,000판 (하루 600판)**. 다른 게임과 한도를 같이 쓰므로 실제 여유는 그보다 적다.
- 동시 접속 : 오락실에 들어와 있으면 이미 1연결이다. 멀티를 해도 **연결 수는 늘지 않는다.** 다만 무료 한도 **동시 100명**은 오락실 전체의 천장이다.
- 더 아끼는 안(1초 2번) : 입력 지연이 0.7초로 늘어 손맛이 나빠진다 → 채택하지 않음.

## 7. 서버 규칙 변경 — 대표님 승인 필요

오락실 RTDB 규칙은 **허용 목록** 방식이다. 목록에 없는 게임 값 · 필드를 쓰면 그 쓰기가 **통째로 거절**된다. 그래서 멀티 단계를 시작하기 전에 아래를 규칙에 넣고 콘솔에 게시해야 한다.

| # | 위치 (`docs/rtdb-rules.json`) | 바꿀 것 |
|---|---|---|
| 1 | `rooms/$code/game` | 허용 값에 `'idragon'` 추가 (지금 : shoes · dragon · catch · jump) |
| 2 | `rooms/$code/idgStage` | 새 필드. 숫자 0~200 (0 = 대결) |
| 3 | `rooms/$code/players/$uid/ld` | 새 필드. 문자열 500자 이하, 본인만 |
| 4 | `rooms/$code/players/$uid/lk` | 새 필드. 문자열 400자 이하, 본인만 |
| 5 | presence 의 `game` | 허용 값에 `'idragon'` 추가 |
| 6 | 받은 편지함 초대의 `game` | 허용 값에 `'idragon'` 추가 (지금 : shoes · dragon · catch) |
| 7 | 통계 `tot/$game` · `g/$game` | 허용 이름에 `idragon` 추가 (**싱글 출시 때부터 필요** — 플레이 횟수 집계) |

- `maxPlayers` 는 2 → 지금 규칙(2~4) 안이라 그대로.
- 싱글 저장(`idg` 묶음)은 Firestore `users/{uid}` 에 들어간다. Firestore 규칙이 필드를 제한하고 있으면 `idg` 도 추가한다 (제작 0단계에서 확인).

**순서** (어기면 쓰기가 전부 거절된다)

1. 규칙 문서 수정 (`docs/rtdb-rules.json` · `docs/FIREBASE_RULES.md`) — 코드와 **같은 커밋**
2. `npm run qa:rules` 통과
3. **대표님 승인** → 콘솔에 게시
4. 그다음에 게임 코드 배포

## 8. 제작 순서와 합격 기준

| 단계 | 할 일 | 합격 기준 |
|---|---|---|
| M1 | 코어 2인 검사 (Node) + 협동 배율 정하기 | 같은 씨앗 · 같은 명령 기록으로 두 번 돌려 **모든 틱의 해시가 같다.** 협동 · 대결 각 100판 |
| M2 | `net/lockstep.js` + 가짜 통신 (한 기기 안에서 지연 0~400ms · 누락 10% 흉내) | 1,000판 자동 대전에서 어긋남 0 · 멈춤 뒤 따라잡기 정상 |
| M3 | 규칙 게시 (7장) → `net/roomBridge.js` · `startIanDragon.js` · 로비 | 폰 2대로 방 만들기 → 초대 → 시작 → 끝 → 한 판 더 |
| M4 | 같이 깨기 화면 · 보상 · 끌어 주기 | 1-1 · 3-5 · 5-10 을 둘이 깬다. 한 명이 중간에 나가도 남은 사람이 끝낸다 |
| M5 | 용 대결 화면 · Lv20 고정 · 전적 | 10판. 무승부 · 시간 종료 · 기권 처리 |
| M6 | 버전 확인 · 끊김 · 뒤로 가기 · 비용 실측 | **폰 2대 · 이동통신에서 20판 : 어긋남 0, 멈춤 판당 1번 이하.** 한 판 내려받기 1MB 이하 |

## 9. 문제와 열린 결정

| # | 내용 | 부장 의견 |
|---|---|---|
| 1 | **입력 지연 0.4초가 맞는지 실측 전이다.** RTDB(싱가포르) 왕복이 늦으면 멈춤이 잦다 | M2 에서 가짜 지연으로, M6 에서 실제 폰으로 재고 9~18틱 사이에서 고정 |
| 2 | **서버 심판이 없다** — 안 가진 용 · 일부러 끊기를 막을 수 없다 | 대결은 친구끼리만, 보상은 작게 (하루 5판) |
| 3 | **RTDB 규칙 게시** 는 손으로, 승인이 있어야 한다 (7장) | 멀티 단계 첫날에 승인 요청 |
| 4 | **무료 한도** — 동시 접속 100 · 월 10GB 를 오락실 전체가 같이 쓴다 | 하루 수백 판까지는 문제없다. 늘면 그때 요금제 |
| 5 | **「새 게임 공식」 문서(`NEW_GAME_RULES.md`)가 다른 가지(plan/cloudflare-1105)에만 있다.** Cloudflare 이전도 검토 중 | 통신을 `roomBridge.js` 한 파일에 가둬 대비. 이전이 정해지면 그 파일만 다시 쓴다 |
| 6 | **협동 배율(1.5배) · 대결 밸런스는 아직 숫자를 안 돌렸다** | M1 에서 계산기로 2인 자동 전투 → 확정. 대결은 AI 대 AI 로 "무조건 이기는 덱"이 없는지 본다 |
| 7 | 대결에서 「얼음 숨결」(전체 4초 얼림)이 너무 셀 수 있다 | M5 에서 확인. 세면 대결에서만 2초 |
| 8 | 끌어 주기(협동으로 첫 클리어 인정)가 월드 보스 "시험"을 쉽게 만든다 | 의도한 것 — 친구와 같이 넘는 벽도 재미다. 싫으시면 「월드 보스는 혼자만」으로 바꾼다 |
