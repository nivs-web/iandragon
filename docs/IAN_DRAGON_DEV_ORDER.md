| 차수 | 내용 | 작업 시간 | 달력 |
|---|---|---|---|

## 1. 시작 전에

### 1.1 읽는 순서

1. [팀 계획서](IAN_DRAGON_TEAM_PLAN.md) — 누가 어느 폴더를 고치는가 (철칙 : 상대 폴더 수정 금지)
2. [기획서](IAN_DRAGON_GDD.md) 0 · 1 · 3 · 5 · 11 · 15장 (그림 담당은 12 · 13장)
3. 이 문서
4. 오락실 저장소 `CLAUDE.md` (오락실 규칙이 이 문서보다 **우선**. 단 PixiJS · 음성 파일은 이 게임만 예외 — 1.4)

### 1.2 무엇이 기준인가

| 종류 | 기준 (이것과 다르면 이것이 맞다) |
|---|---|
| 유닛 · 좀비 · 리더 · 스킬 · 화로 숫자 | `docs/sim/data.js` |
| 스테이지 100개 (적 줄 · 배율 · 시간 · 별 · 보상 · 해금) | `docs/sim/stages.generated.json` |
| 전투 규칙의 세부 (순서 · 반올림 · 예외) | `docs/sim/engine.js` — **기준 구현** |
| 그 밖 전부 (화면 · 그림 · 성장 · 소리) | 기획서 |

**숫자를 손으로 다시 치지 않는다.** 변환 스크립트로 옮긴다 (B1).

### 1.3 어디서 일하나

- 게임 코드 : 오락실 저장소의 **`src/games/iandragon_game/`** (기획서 15.2). 이름은 `iandragon` 저장소(드래곤 스트라이커 · 기획 문서)와 헷갈리지 않게 `iandragon_game`.
- 워크트리 · 가지 : 겜부장 `oraksil/fs-idg` · `feat/iandragon-game` / 겜팀장 `oraksil/fs-idg-art` · `feat/iandragon-game-art` (팀 계획서 3장). `node_modules` 는 `fs-idg/node_modules` 연결 (pixi.js 포함).
- **`oraksil/find_shoes` 원래 작업 폴더는 건드리지 않는다** (다른 작업 중 · 남의 수정 파일 있음).
- 기획 문서 원본은 `iandragon` 저장소 `docs/`. `iandragon` 저장소 루트 `index.html` (드래곤 스트라이커)은 **절대 건드리지 않는다.**
- main 에 올리는 것(= 실제 배포)은 **대표님이 시킬 때만**, 겜부장이.

### 1.4 오락실 규칙 + 이 게임의 예외

- Vite + 순수 JS(ESM, JSDoc) + Web Audio. React · Phaser · Tailwind · GSAP 금지.
- **예외 ① PixiJS v8** — 화면 그리기 전용, 게임에 들어갈 때만 불러온다. `pixijs-skills` 스킬을 보고 v8 문법으로 쓴다.
- **예외 ② 음성 파일** (보이스 스튜디오 · ogg + m4a). 음악 · 효과음은 파형 합성 그대로.
- 도트 : 번짐 없음 · 정수배 확대 · 그림 안 반투명 · 그라디언트 없음. AI 그림 생성 0.
- 캔버스에 브라우저 글꼴로 글씨 쓰기 금지 → 구운 도트 폰트 글자 그림. 한글 문장은 DOM (Neo둥근모).
- 문구는 `src/config/strings.ko.js`, 수치는 `data/`, 좌표는 layout 파일. 화면 코드에 숫자를 박지 않는다.
- 파일 하나 300줄 이하 (그림 데이터는 예외). 화면은 Firebase 를 `services` 로만 부른다.
- 파일 쓰기는 편집 도구 또는 Node 만 (파이썬은 줄바꿈 사고).

### 1.5 금지 목록

| 금지 | 까닭 |
|---|---|
| 다른 영화 · 게임의 캐릭터 · 그림 · 음악 · 스테이지를 닮게 만들기 | 전부 오리지널 (기획서 12.7) |
| AI 그림 생성 · 제미나이 / 버텍스 · Aseprite MCP | 대표님 결정 (비용 · 토큰) |
| 현금 결제 · 광고 · 스태미너 | 기획서 18장 |
| 코어에서 `Math.random` · `Date.now` · `Math.sin/pow/exp` · 화면 값 · Pixi 읽기 | "같은 입력 → 같은 결과"가 깨진다 |
| 상대 담당 폴더 고치기 | 팀 계획서 철칙 |
| 기획에 없는 기능 덧붙이기 | 먼저 대표님께 묻는다 |
| 카드 열기(`ready: true`) · main 배포 · Firebase 규칙 게시 · 엑스트라 사용 | 대표님 승인 사항 |

## 2. 겜부장 블록 (코드)

블록 하나 = 세션 하나를 권한다. **합격 기준을 전부 확인한 뒤** 커밋하고 `docs/IAN_DRAGON_GAME_PROGRESS.md` 에 적고, 겜팀장에게 알리고, 대표님께 보고한다. 겜팀장 블록(A1~A6)은 [팀 계획서](IAN_DRAGON_TEAM_PLAN.md) 4장.

### B0 — 뼈대 · 로비 · 가로 전환 (1.5~2시간)

- `npm i pixi.js@8` · 폴더 (기획서 15.2) · `index.js` 의 `mount(host, opts)` / `unmount` · `src/screens/IanDragonGameLobby.js` (세로 로비 — `DragonLobby.js` 틀) · `src/screens/IanDragonGame.js` (가로 게임 화면, 지연 로딩).
- **가로 전환 (기획서 11.0)** : 「모험 시작」 → 안드로이드는 전체화면 + `lockLandscape()`, 아이폰은 세로면 "가로로 돌려 주세요" + 일시정지, PC 는 450 틀을 벗어난 16:9. 나갈 때 원래대로.
- PixiJS 앱 (`render/app.js`) : 640 × 360 바탕 · 정수배 확대 · 도트 설정 (기획서 12.1).
- `src/services/iandragonGameState.js` — 저장 묶음 `idg` (기획서 14장, 줄넘기 `jumpropeState.js` 방식).
- **빈 자리** : `art/README.md` · `audio/index.js` (팀 계획서 2.2 모양, 아무것도 안 함) · `tools/idg-placeholder.mjs` → 자리표시 그림 시트 · `package.json` 에 겜팀장 스크립트 자리.
- 오락실 카드 : 이미 있는 「제작 중」 카드(2026-11-10 배포)의 id 를 `iandragon_game` 으로 정리, 계속 `ready: false`. 숨은 입구 `?game=iandragon_game` 으로 대표님 · 겜팀장이 배포 없이 들어가 볼 수 있게.
- 확인해서 보고에 적을 것 : Firestore 가 `users/{uid}.idg` 를 받아 주는가 · 통계(`stats.countPlay`)는 규칙에 `idragon` 이 들어간 뒤에만 부른다.

**합격** : 숨은 입구 → 세로 로비 → 「모험 시작」 → 가로 화면에 자리표시 용 · 좀비가 또렷하게(번짐 없이) 보인다 → 나가면 세로 로비 · 저장 묶음이 쓰이고 다시 읽힌다 · `npm run build` 통과 · 기존 게임 6개 영향 없음. → **겜팀장에게 "0단계 커밋 완료" 알림** (그때부터 겜팀장이 자기 가지를 딴다).

### B1 — 전투 코어 + 검사 (2~3시간)

- `docs/sim/engine.js` (516줄)를 `core/` ESM 파일들로 나눠 옮긴다 (파일당 300줄 이하). **계산 순서 · 반올림을 한 글자도 바꾸지 않는다.** 기준 AI(`aiCommands`)도 옮긴다 — 자동 전투 · 검사용.
- 데이터 변환 `tools/idg-import-data.mjs` : `data.js` → `data/units · enemies · leaders · skills · wallet.js`, `stages.generated.json` → `data/stages/w01~w10.js`, `ECON` → `data/econ.js`, **`data/artManifest.js`** (월드별로 필요한 그림 프레임 이름 — 팀 계획서 2.1).
- **골든 파일** : `docs/sim/golden.js` 로 정답표 — 스테이지 100 × 씨앗 101 · 102 · 103 × 기준 빌드 · 기준 AI → `{스테이지, 씨앗, 승패, 시간, hashState}` 300줄.
- `npm run qa:idg-core` : 옮긴 코어로 300판 → 골든과 비교. **틀린 줄만 출력, 다 맞으면 "300/300 OK" 한 줄** (토큰 절약).

**합격** : 300/300 일치 · 코어에 금지 함수 0 (검사 스크립트가 글자 검색) · 코어가 DOM · Pixi · 시계를 부르지 않는다.

### B2 — 전투 화면 (2.5~3시간)

- 가로 화면 틀 (기획서 11.1) : 상단 띠 · 기지 체력 · 전장 · 미니맵 · 불씨 · 화로(왼쪽) · 브레스(오른쪽) · 덱 5 × 2 · 스킬 · 포효 · PC 키보드.
- 고정 간격 루프 (15.3) : 화면 60fps · 코어 1/30초 · 한 프레임 최대 6번.
- 카메라 (11.2) · 유닛 그리기 (1칸 = 1wu) · 그림 시트에서 프레임 찾기 (없는 프레임은 자리표시) · 덱 버튼 상태.

**합격** : 폰 가로 화면에서 1-1 을 30초쯤에 깬다 · 1-10 보스와 충격파 · 유닛 65마리 60fps (PC) · 번짐 없음 · 버튼이 손가락 크기 이상.

### B3 — 연출 · 소리 연결 (1~1.5시간)

- 기획서 11.3 연출 9가지 · 2배속 · 일시정지 · 결과 화면.
- 겜팀장 `audio/index.js` 로 효과음 · 곡 · 음성 연결 (팀 계획서 2.2 id). 겜팀장 가지를 합친다 (합치기 ①).

**합격** : 연출을 전부 꺼도 해시가 같다 · 소리 켬 / 끔이 오락실 설정을 따른다 · 진짜 그림 · 소리로 월드 1 이 돈다.

> **확인 지점 ①** — 대표님 · 이안이 월드 1 을 해 본다 (숨은 입구). 재미 · 빠르기 · 그림 · 음성 의견을 받아 반영.

### B4 — 전투 밖 (3~4시간)

- 지도 (가로) · 스테이지 카드 (오늘의 좀비 · 추천 · 권장 Lv · 별 조건) · 결과 · 용 둥지 · 리더 · 스킬 · 연구소 · 보물 · 아래 탭 5개.
- 경제 (기획서 10장 · `data/econ.js`) · 튜토리얼 · 기능 해금 (9.5) · 졌을 때 힌트 (11.6).

**합격** : 새 계정으로 1-1 → 1-10 이 설명 없이 진행 · 껐다 켜도 · 다른 기기에서도 진행 그대로 · 터치 3번 안에 어느 화면이든 · 코인 · 젬이 수치표 11장과 맞는다.

### B5 — 월드 2~5 (1~1.5시간)

- 기믹 (제한 출격 · 화로 고정 · 보스 러시 · 맞바람 · 안개 · 비용 제한 · 용돈 듬뿍) · 스킬 돌풍 · 얼음 숨결 · 덱 6~9칸 · 레벨 상한 15 · 20 · 3배속.
- 보스 판이 길다는 문제 (기획서 16.4) : 보스 · 러시 판 `baseHp` 15~20% 낮추고 시작 (추천안 9장 3번) — 계산기 원본도 같이 고친다.

**합격** : 기준 AI 자동 전투로 1-1 → 5-10 을 화면에서 차례로 돌려 전부 끝난다 · 골든 검사 통과.

### B6 — 부화장 · 도감 · 과제 (1~1.5시간)

- 부화장 (뽑기 용 5종 · 1개 / 10개 · 확률 표시 · 천장 · 겹치면 「+」 · **현금 없음**) · 도감 · 도전 과제 (1차 분량) · 매일 첫 승리 · 자동 전투 버튼 (별 1개 이상 딴 스테이지만).

**합격** : 뽑기 1만 번 Node 검사로 확률 ±1% · 천장 50 안에 전설.

### B7 — 마감 (1~1.5시간)

- 폰 · PC 확인 · 보급형 폰 성능 · 겜팀장 가지 최종 합치기 ② · 300줄 넘는 파일 나누기 · 맞춤법 · 도트 폰트 빠진 글자.
- 1차 끝 화면 : 5-10 을 깨면 "다음 이야기는 곧!" 한 장.

**합격** : `npm run build` · 오락실 기존 검사 전부 · 골든 검사 · 알려진 오류 0 → **확인 지점 ②** → 대표님이 시키시면 카드 열기 + main 배포.

| 느낌 | 고칠 곳 |
|---|---|
| 스테이지가 너무 어렵다 / 쉽다 | 그 스테이지의 `mag` (좀비 체력 배율) · `atkMag` (공격 배율 = mag × 2) |
| 너무 길다 / 짧다 | `baseHp` (좀비 탑 체력) |
| 시간이 빡빡하다 | `limit` · 별 조건 (`star2` · `star3`) |
| 용 하나가 너무 세다 / 약하다 | `docs/sim/data.js` 의 그 용 → **계산기를 다시 돌린다** (`node tune.js` → `node gen-docs.js` → 변환 스크립트 → 골든 다시 뽑기) |
| 코인이 모자란다 / 남는다 | `gen-docs.js` 의 `ECON` |

- 스테이지 숫자 3개(`mag · baseHp · limit`)는 게임 쪽 데이터에서 바로 고쳐도 되지만 **원본(`stages.generated.json`)도 같이** 고친다.
- 전투 규칙 · 유닛 숫자를 바꾸면 골든이 달라진다 → 계산기 수정 → 골든 → 게임 코어 순서.
