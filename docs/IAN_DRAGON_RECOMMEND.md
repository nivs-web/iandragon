## 1. 그림 — "픽셀이 너무 크게 보이지 않는 도트"

### 1.1 부드럽게 그리면 도트인가?

**아니다.** 기준은 그리는 방식이다.

- **도트** = 정해진 칸(격자)에 한 칸씩 색을 찍은 그림. 확대할 때 번지지 않게(nearest) 보여 준다. 칸이 작으면 또렷하고 촘촘해 보이고, 칸이 크면 레트로처럼 보인다.
- **고해상도 그림** = 선과 면을 부드럽게(안티에일리어싱) 그린 그림.
- **PixiJS 는 붓이 아니라 화면에 빨리 보여 주는 엔진**이다. 도트를 넣으면 도트 게임, 부드러운 그림을 넣으면 고해상도 게임이 된다.

대표님이 말씀하신 것 = **"촘촘한 도트"** (메이플스토리처럼 칸이 작아서 픽셀이 거슬리지 않는 도트). 도트가 맞다.

### 1.2 숫자로 보면

| | 굵은 도트 (지금 기획서) | **촘촘한 도트 (추천)** | 고해상도 |
|---|---|---|---|
| 화면 바탕 | 세로 기준 215~270칸 | **가로 640 × 360칸** | 기기 해상도 |
| 작은 용 | 16 × 16칸 | **32 × 32칸** | 64~72px |
| 보스 | 56~72칸 | **96~128칸** | 200~260px |
| 같은 크기 용을 몇 칸으로 | 16 × 16 = 256칸 — 계단이 크게 보인다 | **32 × 32 = 1,024칸 (4배 촘촘) — 계단이 거의 안 보인다** | — |
| PC 1080p 에서 한 칸 | — | 화면 점 3개 (요즘 인디 도트 게임 느낌) | — |
| Claude 실력 | 작아서 실수가 묻힘 | 부품 조립 + 확인 루프로 버틴다 | 선 · 비율 실수가 그대로 보임 |
| 그림 시간 (부품 방식) | 10~14시간 | **12~16시간** | 14~20시간 |

- 640 × 360 은 **1080p 의 딱 1/3** 이라 대부분의 폰 · PC 에서 정수배(×2 · ×3)로 또렷하게 커진다. 화면이 더 긴 폰(19.5:9)은 좌우로 전장이 조금 더 보인다.
- 캐릭터 크기 비율은 냥코 대전쟁과 비슷하다 (작은 용 ≈ 화면 높이의 9%).

### 1.3 시간을 줄이는 그림 규칙 (모두 냥코 대전쟁이 실제로 쓰는 방식)

| 규칙 | 줄어드는 것 |
|---|---|
| **부품 조립** — 몸통 · 머리 · 눈 · 입 · 날개 · 뿔 · 꼬리 · 다리 부품 약 40개를 만들고, 용 한 마리 = "어떤 부품 + 색 3개 + 크기" 한 줄 | 100종을 하나하나 그리지 않는다 |
| **속성 좀비 = 색만 바꾼 좀비** (빨강 · 얼음 · 강철 · 유령 …) | 좀비 33종 → 몸 약 18개 + 색 |
| **진화 = 부품 추가 + 색 진하게 + 크기 +4칸** | 진화 46장이 거의 공짜 |
| **움직임 = 부품을 1~2칸씩 옮기기 + 다리 2장 교체** (회전 없음 — 도트를 돌리면 깨진다) | 캐릭터마다 프레임을 새로 안 그린다 |
| 중간 보스 = 좀비 2배 + 왕관 (기획서 그대로) | 9장 절약 |

### 1.4 품질 장치 (Claude 그림이 약한 것을 메우는 법)

1. **팔레트 고정** — 게임 전체 40색 안팎. 캐릭터마다 밝음 · 보통 · 그림자 3단 + 1칸 외곽선.
2. **실루엣 먼저** — 검은색으로만 칠해도 누군지 보이는지 확인한 뒤 색을 칠한다.
3. **확인 루프** — 그림 → 실제 크기 · 2배 · 같은 월드 친구들과 나란히 놓은 시트를 스크린샷으로 보고 → 고친다. (Aseprite MCP 를 만든 사람들의 결론도 같다 : LLM 도트는 "보고 고치는 도구"가 있어야 좋아진다.)
4. **대표님 승인 지점** — 꼬물이 · 돌등이 · 어슬렁 좀비 3장을 먼저 보여 드리고, OK 가 나야 나머지를 만든다.

## 2. PixiJS — 자세히

| 항목 | 내용 |
|---|---|
| 정체 | 웹용 **2D 그래픽 엔진**. 그림(스프라이트)을 GPU(WebGL · WebGPU)로 아주 빨리 그려 준다 |
| 버전 | **v8.22.0** (2026-10-01) · **MIT — 무료, 상업 사용 가능** |
| 크기 | 전체 묶음 약 840KB (압축 전송 시 약 250KB 안팎). **이안 드래곤을 누를 때만 받는다** → 오락실 첫 화면 속도에는 영향 없음 |
| 잘하는 것 | 수천 개 그림을 한 번에 묶어 그리기 (용 · 좀비 65마리 + 불꽃 · 먼지 · 숫자도 60fps) · 스프라이트 시트 · 프레임 애니메이션 · 파티클 · 필터 (맞으면 하얗게 번쩍, 불꽃 타임 테두리 빛) · 카메라 이동 · 확대 · 터치 |
| 도트 설정 | 번짐 없음(`scaleMode: 'nearest'`) · 안티에일리어싱 끔 · 좌표 반올림(`roundPixels`) · 640 × 360 에 그려서 정수배로 키우기 → 도트가 또렷 |
| 우리 게임에서 맡는 일 | **화면만.** 전투 계산(코어)은 지금 만든 `engine.js` 그대로 — Pixi 와 섞지 않는다 (멀티 · 자동전투 · 검사가 그래서 안전) |
| 시간 효과 | 렌더러 · 카메라 · 묶어 그리기 · 이펙트를 직접 안 짜도 돼서 **1~2시간 절약**, 성능 걱정 감소 |
| 주의 | ① 오락실 규칙에서 금지였다 → **이 게임만 예외**로 적어 둔다 ② 예전 v7 문법과 헷갈리기 쉽다 → 공식 **pixijs-skills** 설치로 막는다 (7장) ③ 글자는 지금처럼 화면 위 DOM 또는 도트 글꼴 그림 (`fillText` 금지 유지) |

## 3. 화면 흐름 — 로비는 세로, 게임은 가로

```
[이안오락실 첫 화면 · 세로] → [이안 드래곤 로비 · 세로]
                                  로고 · 모험 시작 · 이어하기 · 멀티(나중) · 기록 · 설정 · 도움말
                                     │  「모험 시작」
                                     ▼
                          ┌──────── 가로 화면 ────────┐
                          │ 월드 지도 → 스테이지 카드 → 전투 → 결과 │
                          │ 용 둥지 · 부화장 · 연구소 · 도감 (아래 탭) │
                          └───────────────────────────┘
                                     │  「로비로」
                                     ▼
                              [로비 · 세로]
```

- **폰을 돌리는 건 들어갈 때 한 번, 나올 때 한 번.** 판마다 돌리지 않는다 (냥코도 메뉴 · 전투 전부 가로).
- 안드로이드 : 전체화면 + 가로 잠금 (오락실에 이미 `lockLandscape()` 가 있다).
- 아이폰 : 잠금이 안 된다 → 세로로 들고 있으면 "📱 가로로 돌려 주세요" 화면 + 자동 일시정지.
- PC : 돌릴 것 없음. 게임 화면만 창 크기에 맞춘 16:9 (450 틀 예외).
- 로비는 신발 · 드래곤 스트라이커 로비 파일(`Lobby.js` · `DragonLobby.js`)의 틀을 그대로 가져온다 → 새로 짜는 양이 적다.

가로 전투 화면 (냥코식 배치 — 왼손 화로 · 오른손 브레스 · 가운데 덱) :

## 5. 제작 시간 — 줄이는 방법

### 5.1 기준 (지난 보고) → 대표님 말씀 반영 후

| 범위 | 시간 (Opus 5.5 높음) |
|---|---|
| 지난 보고 : 싱글 100스테이지 | 30~40시간 |
| 지난 보고 : 멀티까지 | 40~55시간 |
| 가로 · 로비 · PixiJS · 음성 연결 · 촘촘한 도트 반영 (싱글 100) | **30~40시간** (Pixi 로 줄고 가로 · 로비 · 음성으로 늘어 비슷) |

### 5.2 줄이는 방법

| 방법 | 줄어드는 시간 |
|---|---|
| **A. 1차 = 월드 1~5 (50스테이지)** — 스테이지 100개 수치는 이미 다 있다. 그림 · 보스만 절반 | 약 −35% |
| **B. 속성 좀비 = 색 바꾸기** | −1~2시간 |
| **C. 진화 3모습 중 3단은 2차로** (1차는 기본 + 진화 1번) | −1.5~2시간 |
| **D. 뽑기 용 11종 → 1차 5종** | −1~1.5시간 |
| **E. 멀티는 3차** | −10~15시간 |
| **F. 그림 세션 + 코드 세션 동시 진행** (다른 폴더 · 다른 파일이라 안 부딪힘) | 달력 −30~40% (토큰은 같음) |
| **G. 노력 단계 조절** (6장) | 토큰 −20~30% (추정) |
| 이미 있는 것 쓰기 : 전투 코어(`engine.js`) · 스테이지 100개 수치 · 오락실 로비 틀 · 방 · 소리 엔진 · 저장 | 지난 추정에 이미 반영 |

### 5.3 추천 일정

| 차수 | 내용 | 작업 시간 | 달력 (하루 6~8시간, F 적용) |
|---|---|---|---|
| **1차** | 로비 · 가로 전환 · 월드 1~5 (50스테이지) · 스토리 용 10 + 뽑기 용 5 · 음성 · 오락실 카드 | **16~22시간** | **2~3일** |
| 2차 | 월드 6~10 · 3단 진화 · 나머지 뽑기 용 6 · 엔딩 | 12~16시간 | 2일 |
| 3차 | 멀티 (같이 깨기 · 용 대결) | 10~15시간 | 2일 |

±30%. 대표님 확인을 기다리는 시간과 고치기(+20~30%)는 빠져 있다. 1차 중간에 **확인 지점 2번** : ① 그림 3장 샘플 (첫날) ② 월드 1 플레이 판 (첫날~둘째 날).

## 6. Opus 5.5 — 높음 vs 엑스트라(X하이)

- **엑스트라는 "빠르게"가 아니다.** 한 걸음마다 더 오래 생각하는 단계라 **시간도 토큰도 더 든다.** 대신 어려운 설계에서 실수가 줄어든다.
- 이 게임에서 진짜 어려운 곳은 두 군데뿐이고, 나머지는 정해진 틀을 채우는 일이다.

| 단계 | 노력 | 이유 |
|---|---|---|
| 0 뼈대 · 로비 · 가로 전환 · PixiJS 설치 | 높음 | 오락실 구조를 처음 읽는 단계 |
| **1 전투 코어 옮기기 + 300판 정답 검사** | **엑스트라** | 숫자 하나만 틀려도 자동전투 · 멀티 · 밸런스가 다 깨진다 |
| 2 전투 화면 + 그림 부품 키트 + 월드 1 그림 | 높음 | 그림 기준을 세우는 단계 |
| 3 타격감 · 효과음 · 음성 연결 | 중간 | |
| 4 지도 · 둥지 · 부화장 · 저장 · 튜토리얼 | 높음 | |
| 5 월드 2~5 채우기 | **중간** | 같은 틀 반복 |
| 6 뽑기 · 도감 · 도전 과제 | 중간 | |
| 7 마감 · 오락실 연결 · 배너 | 높음 | 품질 확인 |
| (3차) 멀티 | **엑스트라** | 두 기기 동기화는 어렵다 |

→ **추천 : 기본 높음, 1단계와 멀티만 엑스트라, 반복 단계는 중간.** 전부 엑스트라보다 토큰이 크게 덜 들고, 전부 중간보다 큰 실수가 적다.
- 단계마다 **새 세션** + `docs/IAN_DRAGON_PROGRESS.md` 이어받기 (긴 대화가 쌓이면 매 걸음 토큰이 늘어난다).

## 7. 토큰 절약 — 깃허브 조사 결과

### 7.1 가장 큰 구멍 : 오락실 CLAUDE.md

- 오락실 저장소의 `CLAUDE.md` 는 **약 6,000줄 · 424KB** 다 (8월부터의 기록이 다 들어 있다).
- Claude Code 는 세션을 시작할 때마다 이 파일을 읽어 들인다 → **세션마다 큰 토큰이 먼저 나간다** (추정 10만 토큰 이상).
- **추천 : 핵심 규칙(1~8장, 약 300줄)만 남기고 9장 이후 기록은 `docs/HISTORY.md` 로 옮긴다.** 필요할 때만 열어 본다. 이안 드래곤뿐 아니라 **오락실의 모든 작업**이 싸진다.
- 다른 게임 작업(겜팀장)도 이 파일을 쓰므로 **대표님 승인 후** 한 번에 한다. 도구 : `claude-token-optimizer` (MIT · ⭐600+ — 오래된 기록을 옆 파일로 옮겨 주는 도구) 또는 손으로.

### 7.2 설치 추천

| 순위 | 도구 | 하는 일 | 판단 |
|---|---|---|---|
| 1 | **RTK** (rtk-ai/rtk · ⭐86k · Apache-2.0 · 오늘도 갱신) | 빌드 · 검사 · git 같은 **명령 출력을 60~90% 압축**해서 Claude 에게 넘긴다 | **추천.** 우리 제작은 빌드 · 300판 검사 출력이 많다. 단, 만든 쪽도 "출력 90% 절약 ≠ 요금 90% 절약"이라고 밝힌다 — 전체로는 10~25% 안팎 기대(추정). **윈도우(Git Bash)에서 먼저 시험** |
| 2 | **pixijs-skills** (PixiJS 공식 · MIT) | Claude 에게 PixiJS v8 올바른 사용법을 가르치는 스킬 | **PixiJS 를 쓰면 필수.** 틀린 문법 → 다시 짜기를 막는 것이 곧 토큰 절약 |
| 3 | Serena (oraios/serena · ⭐31k) | 파일을 통째로 안 읽고 함수 단위로 찾고 고친다 | 선택. 오락실 저장소가 커서(파일 650개) 도움이 되지만 Python 설치가 필요 |
| ✗ | Caveman (⭐118k) | 답을 원시인 말투로 줄여 **출력** 토큰 65%↓ | 비추천 — 대표님 보고가 딱딱하고 짧아진다. 출력보다 입력(읽기)이 훨씬 크다 |
| ✗ | Headroom 등 프록시 | 압축 중계 | 비추천 — 유료이거나 계정을 중간에 거친다 |

### 7.3 설치 없이 되는 습관 (제작 명령서에 넣을 것)

- 검사 스크립트는 **틀린 줄만** 출력 (300판이 다 맞으면 한 줄 "300/300 OK").
- 큰 출력은 파일로 받고 요약만 본다.
- 그림 확인 스크린샷은 축소해서 찍는다.
- 단계마다 새 세션, 진행 기록 파일로 이어받기.

## 10. 따로 보고 — 오락실 신작 카드

- 「이안 드래곤」 카드를 **신발을 찾아서 위**에 넣었다 : 제목 · NEW · 제작 중 · SOON 버튼(누르면 "지금 만드는 중이에요" 안내). 아래 준비 중 자리는 "8번째 게임 준비 중".

- **실제 사이트(main)에 올리는 단계는 자동 권한 검사가 "운영 배포"로 막아서 멈췄다.** 대표님이 "올려"라고 하시면 다시 시도하고, 그래도 막히면 권한 설정에서 허용이 필요하다.
